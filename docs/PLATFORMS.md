# Commands and modes by platform

Checked against primary documentation on **2026-10-26**. The table describes the
files generated by Uni Learn setup and each host's documented entry point.
Documentation research and generated adapter tests are separate from live editor
certification; the existing live sample covers Codex, not all twelve hosts.

The seven moves are `learn`, `learn-hint`, `learn-debug`, `learn-review`,
`learn-design`, `learn-recall`, and `learn-compact`. Apply each host's prefix to
the move: `/learn-hint`, `$learn-hint`, `/skill:learn-hint`, or
`/uni-learn-hint`. For Aider, load the corresponding Markdown file.

## A learning preference and a native mode are different controls

On hosts exposing `/learn`, send:

```text
/learn on
/learn Explain this project's authentication flow.
/learn off
```

Use `$learn on` in Codex CLI/IDE, `/skill:learn on` in Kimi, or `/uni-learn on`
in Antigravity. In Aider, first load the `learn.md` file, then send `learn on`
as an ordinary request. `/read` accepts file paths, so do not append `on` as if
it were another file.

The native entry point loads a prompt, skill, or reference file. Its dispatcher
asks the assistant to execute Uni Learn's runtime, which stores the project's
preference. A single explicit learning move works while the preference is off.
This does not register a built in editor mode, change the host's Plan/Ask/Act
selector, or grant additional tool permissions. Host restrictions on executing
commands still apply. Start a fresh chat after turning learning off to clear
teaching instructions already loaded into the current conversation.

## Installation scope

```sh
python3 uni-learn.pyz setup --host claude-code --project /path/to/project
python3 uni-learn.pyz setup --host opencode --project /path/to/project
python3 uni-learn.pyz setup --host antigravity --project /path/to/project
python3 uni-learn.pyz setup --host windsurf --generation devin-desktop --project /path/to/project
```

Use any profile from the table. The remote installer accepts the same arguments
and defaults project scope to the current directory when `--project` is omitted.
Codex setup defaults to user scope; `--scope project` selects one repository.

Many hosts also document personal skill directories. Uni Learn currently supports
automatic personal setup for Codex only. Other profiles use the project paths
listed above; vendor support for a personal location does not mean this installer
writes there. No editor, extension, or model account is installed by setup.

## Platform details

- **Codex:** CLI/IDE documentation describes `$` and `/skills`. The desktop app's
  `/` menu lists enabled skills. Do not generalize one surface's menu behavior to
  every Codex client. Legacy `/prompts:<name>` custom prompts are deprecated;
  the normal setup installs native skills. Restart if a new skill is not visible.
- **Claude Code:** project skills register `/skill-name`. The generated
  `disable-model-invocation: true` keeps them available only when invoked by the
  user. Claude's own built in
  Plan Mode remains independent of the `on` argument passed to Uni Learn.
- **Copilot VS Code:** open the Chat `/` menu to select the skill. Workspace
  policy, trust, and customization settings can affect availability. The same
  `/skills` management UI is not guaranteed across every VS Code harness.
- **Copilot CLI:** `/skills` manages skills; `/learn` invokes this skill.
  After installing during a session, use `/skills reload` or restart.
- **Cursor:** skills can be invoked with `/skill-name`; attaching a skill as
  context with `@` is a separate affordance. The adapter uses native slash skills.
- **OpenCode:** a SKILL.md alone is discovered through the native `skill` tool.
  Setup also writes seven small command wrappers, providing `/learn*` shortcuts
  that load the matching skill and forward `$ARGUMENTS`. It does not register an
  agent named `learn`, so `@learn` is not the advertised command.
- **Antigravity:** the host's built in `/learn` reflects on corrections and
  proposes persistent rules or skills. Uni Learn uses `/uni-learn*` to avoid that
  collision. Explicit frontmatter names supply these identifiers; keeping the
  existing folders permits owned installations to upgrade safely. The runtime
  still receives canonical `learn*` IDs. The metadata does not prevent automatic
  invocation, so the dispatcher checks the saved preference and stops when
  learning is off unless the user explicitly invokes a Uni Learn command.
- **Gemini CLI:** the adapter writes TOML custom commands, not Markdown slash
  files. Use `/commands reload` after changes, or restart.
- **Kimi Code:** `/skill:learn` is the unambiguous skill spelling. The `/learn`
  shorthand depends on the absence of another command with that name.
- **Devin Desktop:** `--generation devin-desktop` selects current Devin Local,
  which shares CLI skills and `/skill-name` invocation. Legacy Cascade's `@skill`
  mentions and workflows for Cascade alone are different surfaces; this adapter does
  not promise those behaviors for Devin Local.
- **Cline:** enable the skill and invoke it from `/`. Cline can also select skills
  automatically. The generated metadata does not prevent automatic invocation;
  its dispatcher checks the saved preference and stops when learning is off
  unless the user explicitly invokes a Uni Learn command.
- **Aider:** `/read` loads instructions into the conversation. It does not
  register a `/learn` command or automatically load a project preference every
  turn. Aider's native [chat modes](https://aider.chat/docs/usage/modes.html) and
  command execution workflow remain separate; runtime execution can need the
  user's native `/run` workflow.

## Checking an installed version

Run setup in a disposable project, start a fresh host session, and confirm the
entry appears in that host's command or skill surface. Then test `on`, a learning
request, a hint after an attempt, and `off`. Check the runtime result rather than
assuming a prompt changed the stored preference. Verify ordinary learning off work
and a new project retain the expected behavior.

The [testing guide](TESTING.md) separates deterministic adapter/install checks,
native loading, and actual model behavior. Missing host versions or unavailable
menu observations remain unverified; source documentation is not a live test.
